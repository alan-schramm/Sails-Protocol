# Whitepaper Visual Assets

These files are **visual translations of Institutional Truth**. They are not protocol, architecture, product, or implementation authority.

> **Documents define the architecture. Diagrams represent it. If a diagram conflicts with canonical documentation, the documentation governs.**

## Structure

- `protocol/` — visuals for the Sails Protocol Whitepaper
- `technical/` — visuals for the Sails Technical Paper
- `sdk/` — visuals for the Sails P2P Trading SDK Paper

Each visual should keep an editable `.mmd` Mermaid source beside its preferred `.svg` render.

## Claim discipline

A visual may simplify presentation, but it must not:

- introduce a new protocol rule;
- collapse distinctions that canonical documents keep separate;
- upgrade Implementation into Architecture;
- upgrade Architecture into Protocol identity;
- present Roadmap or Future Vision as Implemented;
- imply technological dependency where Sails only adopts a capability.

Where applicable, source comments identify the canonical document used to validate the visual.
