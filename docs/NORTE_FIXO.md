### Sails Protocol — Strategic Macrofront Map

> Recorded 2026-09-04, following the Independent Master Backlog Audit's
> finding that the exact 38-macrofront strategic map, previously
> referenced only in passing (`docs/GITHUB_PROJECT.md` §2, "reconciling
> the GitHub Project against the Master Backlog / Norte Fixo"), did not
> exist as a durable artifact anywhere in this repository or its git

> nothing more.

## What this document is, and is not

- **Norte is not protocol semantics.** It carries no Kernel, Core,
  Constitution, or invariant meaning. Nothing here binds economic
  behavior.
- **Norte is not normative architecture.** It does not describe how
  Sails works technically. See `docs/CORE_ARCHITECTURE.md`,
  `docs/SEMANTIC_KERNEL.md`, `docs/PROTOCOL_INVARIANTS.md` for that.
- **Norte is strategic institutional memory.** It exists so that
  strategic direction and priority can survive the disappearance of any
  single person who currently holds it in conversational memory —
  nothing more, nothing less.

## The distinction this repository now preserves explicitly

```
Master Backlog (docs/BACKLOG.md, docs/TECHNICAL_DEBT_AUDIT.md)
  remembers everything — completed work, known debt, historical
  decisions, in full technical detail.

Norte Fixo (this document)
  prevents strategic blindness — a fixed map of the macrofronts that
  matter, independent of which are currently staffed, funded, or
  in progress.

GitHub Project ("Sails Protocol — Development")
  tells us what state the work is in — operational, day-to-day
  tracking of open, in-progress, and closed items.
```

None of the three is a substitute for either of the other two. A
macrofront listed here may have zero, one, or many Project items; it
may have extensive or minimal Master Backlog representation; its
presence here asserts only that it is a real strategic front, not that
work on it is scheduled, funded, or even currently intended to start.

## Known coverage gaps, as of the 2026-09-04 audit

The Independent Master Backlog Audit found 13 of the 38 fronts above
with weak-to-nonexistent durable representation elsewhere in this
repository (Human & Agent Interaction; several buried inside the
GitHub Project's "Final Evidence Program" card rather than tracked as
their own front — Final External Cold Red Team, Final Product ↔
Protocol Boundary, Master Backlog Closure; among others). This document
does not resolve that — recording the map itself is the fix this pass
is authorized to make. Closing individual coverage gaps remains future,
separately-authorized work.

## Maintenance discipline

This list is itself durable, not append-only in the `INV-05` evidentiary
sense — it may be corrected if a front's name changes or a genuine
strategic error is found, by direct edit with a dated note explaining
the change, the same discipline `docs/BACKLOG.md` and
`docs/TECHNICAL_DEBT_AUDIT.md` already use for their own corrections.
It should not grow a scoring system, a status field, or automation
around it — that would turn strategic memory into another operational
tracker, duplicating the GitHub Project's own role.
